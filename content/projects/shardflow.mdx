## Overview

**ShardFlow** is a high-performance, general-purpose distributed LLM inference framework that partitions any Hugging Face transformer across N heterogeneous GPU machines (such as free Kaggle/Colab notebooks, rented cloud GPUs, or local consumer rigs).

ShardFlow combines **neural speculative decoding (K=8 on dual-GPU nodes)**, **zero-copy binary tensor serialization**, and **high-throughput AWS EC2 TCP relay transport** to overcome wide-area network latency (WAN) and deliver interactive LLM inference speeds across separate cloud data centers.

## Key Technical Innovations

- **Dual-GPU Pipelined Draft Generation:** On Node 0 (2x T4 GPUs), placed the 7B target slice on `cuda:0` (7.64 GB VRAM) and the 0.5B draft model (`Qwen2.5-0.5B-Instruct`) on `cuda:1` (0.98 GB VRAM), eliminating VRAM contention and CPU python wrapper overhead.
- **Exact KV Cache Synchronization & Rollback:** Aligned `DynamicCache` states between draft and target models across WAN. When Node 1 verifies candidate tokens and accepts M tokens, both caches are rolled back to the exact same committed length, eliminating context drift and ensuring up to **58% draft acceptance**.
- **AWS EC2 Zero-Copy TCP Relay Bridge:** Built a low-latency Rust TCP relay (`t3.micro`, Ohio) that bridges NAT firewalls across cloud notebook environments. Binary activations are serialized as raw FP16 buffers with 8-byte length prefixing (`>Q`), cutting CPU serialization time to under 1.5 ms.
- **Zero-RAM Meta-Device Model Slicing:** Instantiates model architectures on PyTorch's `meta` device in **0.00s with 0 MB CPU RAM overhead**, streaming safetensors directly into GPU VRAM.
- **OpenAI-Compatible API:** Exposes standard `POST /v1/chat/completions` streaming endpoints for seamless client and agent integration.
